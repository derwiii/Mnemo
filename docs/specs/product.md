# Mnemo: продукт, ограничения и архитектура

Обновлено 19 ноября 2026. Действующие требования. Настройка палитры, поставка шрифта и оформление окна описаны в спецификации дизайна.

Этот документ определяет цели, границы продукта, общие ограничения и устройство приложения. [Карта спецификаций](../../spec.md).

## 1. Цель и контекст

Бесплатное, понятное десктопное приложение для изучения слов и фраз с помощью карточек. Существующие аналоги платные и непрозрачные в использовании. Пользователь сам создаёт колоды и карточки, может массово импортировать их из JSON (полученного вне приложения, например с помощью ИИ из документа, PDF или изображения), а система повторения адаптируется к ответам пользователя: сложные карточки показываются чаще.

### 1.1 Цели

- G1. Простое управление колодами и карточками (CRUD) через UI.
- G2. Массовый импорт карточек из JSON в выбранную или новую колоду.
- G3. Адаптивное повторение на основе истории ответов.
- G4. Работа полностью офлайн, данные хранятся локально.
- G5. Понятный интерфейс: новый пользователь начинает заниматься без инструкции.

### 1.2 Не цели (v1)

- Синхронизация между устройствами, аккаунты, облако.
- Мобильные приложения.
- Распознавание текста (OCR) и разбор PDF/изображений внутри приложения. Это делается снаружи, приложение принимает только готовый JSON.
- Аудио, озвучка, произношение.
- Социальные функции, публичный каталог колод.
- Монетизация.

### 1.3 Пользователь

Один локальный пользователь, изучающий иностранный язык. Технически может не разбираться, но способен получить JSON у ИИ-ассистента, если ему дать готовый промпт (см. [помощь с JSON](import-export.md#4-помощь-с-получением-json)).

## 2. Глоссарий

- **Колода (Deck)**: именованный набор карточек.
- **Карточка (Card)**: единица изучения: слово/фраза + перевод(ы) + примеры + подсказки.
- **Повторение (Review)**: один показ карточки и ответ пользователя.
- **Оценка (Grade)**: самооценка пользователя: «Не помню» на вопросе либо одна из трёх успешных оценок после раскрытия ответа.
- **Сессия (Session)**: серия повторений за один заход.
- **Лимит**: ограничение исходного набора или дневной выборки; возвраты ошибок могут увеличить число попыток. Дневные лимиты по умолчанию отключены, N в конструкторе ограничивает только число уникальных карточек исходного набора.

## 3. Хранение

Локальная база SQLite в каталоге данных пользователя (на Windows: `%APPDATA%\Mnemo\`). Данные никогда не хранятся внутри папки приложения, чтобы пересборка или удаление папки не уничтожали прогресс. ReviewLog никогда не изменяется и не удаляется иначе как каскадом при удалении карточки.

## 4. Нефункциональные требования

- NFR-1. Стек: Python 3.11+ и PyQt6 (см. раздел 5). Целевая платформа: Windows 10/11 x64. Другие ОС не целевые и не тестируются (код специально не привязывается к Windows там, где это не нужно, но поддержка не обещается).
- NFR-9. Поставка: приложение собирается PyInstaller в режиме onedir (папка с `.exe` и библиотеками), без консольного окна. Подробности в разделе 5.
- NFR-2. Полностью офлайн; никакого сетевого доступа и телеметрии.
- NFR-3. Запуск до 3 секунд, переключение между карточками без заметной задержки при колоде до 10 000 карточек. Проверка введённого ответа по 1–10 вариантам выполняется локально без заметной задержки; время зависит от длины строк и числа вариантов и не объявляется константным.
- NFR-4. Данные пользователя не теряются при аварийном завершении (транзакции SQLite).
- NFR-5. Интерфейс: клавиатурная навигация в режиме повторения; читаемый шрифт с поддержкой кириллицы и основных европейских языков (Unicode везде).
- NFR-12. Главное окно оформлено без видимого системного заголовка. Кнопки окна встроены в общую шапку. Перетаскивание, изменение размера, штатные переходы в панель задач и оформление значка определены в [спецификации дизайна](design.md#2-окно-сетка-и-отступы).
- NFR-6. Оформление тёмное, с выбором готовой палитры в настройках. По умолчанию «Мягкая медь»; остальные схемы и токены определяет [дизайн](design.md#4-цвет). Выбор сохраняется локально и применяется ко всем экранам, диалогам и быстрому вводу без потери текущего состояния. Светлая тема в этот объём не входит.
- NFR-7. Бесплатное, без платных функций. Проект личный (пет-проект): публикация исходников максимум «как есть», без планов развития и поддержки. PyQt6 распространяется под GPL v3 (либо коммерческой лицензией), поэтому при публикации лицензия проекта должна быть совместима с GPL. При необходимости UI-слой можно перенести на PySide6 (LGPL) с небольшими правками.
- NFR-8. Интерфейс только на русском языке. Система локализации не нужна, строки могут лежать прямо в UI-коде (желательно в одном модуле констант).

## 5. Стек, архитектура и поставка

**Стек:** Python 3.11+, PyQt6 (Qt Widgets), `sqlite3` из стандартной библиотеки, `pytest` для тестов.

**Слои и зависимости:**

1. `ui`: окна и виджеты на PyQt6; бизнес-правила вынесены из виджетов.
2. Сервисный слой (`services.py`) связывает сценарии приложения, доменные правила и репозитории.
3. `domain`: модели, `Scheduler`, нормализация и сравнение ответов, валидация импорта. Не импортирует Qt, SQLite или `storage`; покрывается автономными тестами.
4. `storage`: репозитории поверх SQLite, использующие доменные модели; не импортирует Qt.

Координация домена и хранилища выполняется сервисным слоем; домен остаётся независимым от хранилища.

Такое разделение нужно, чтобы алгоритм повторения, импорт и проверку ответов можно было тестировать без запуска GUI.

**Внешний вид (риск R1: «PyQt6 может выглядеть устаревшим»):**
- Единый шаблон оформления с токенами выбранной тёмной палитры; локально поставляемый Manrope, единая сетка отступов и крупная типографика сессии. Контурные SVG-обложки, шрифт и их лицензии входят в ресурсы приложения.
- Готовой темы нет, поэтому пишем собственный QSS без сторонних тем. Стили лежат в одном шаблоне `theme.qss`, цвета подставляются из выбранной палитры в `theme.py`. Одна смена схемы обновляет все открытые окна, стили и цвета SVG без пересоздания учебного состояния.
- Запасной вариант, если Widgets не устроят: переписать только UI-слой на QML (Qt Quick). `domain` и `storage` при этом не меняются.

**Упаковка (обязательна для v1):**
- PyInstaller, режим `--onedir`, оконное приложение (`--windowed`, без консоли). Результат: папка `dist/Mnemo/` с `.exe`; передаётся как архив (zip). Установщик и автообновление не делаем.
- Конфигурация сборки лежит в репозитории (`.spec`-файл и скрипт сборки), чтобы сборка воспроизводилась одной командой.
- Ресурсы (QSS, шрифты, иконки) подключаются через единую функцию получения пути, которая работает и при запуске из исходников, и из собранной папки.
- Критерий приёмки: собранное приложение запускается на чистой Windows без установленного Python, создаёт базу в `%APPDATA%`, проходит основной сценарий (создать колоду, импортировать JSON, пройти сессию) и стартует не дольше 3 секунд.

## 6. Вне рамок v1

- Обратное направление карточек (перевод → слово) как отдельный режим.
- Экспорт и импорт прогресса.
- Теги и фильтрация сессий по тегам.
- Картинки на карточках.
- Озвучка.
- Синхронизация.
- Продвинутый алгоритм (FSRS).

## 7. Статус и открытые вопросы

Базовые этапы 1–8, свободное повторение, статистика, базовый конструктор, входящие и разметка реализованы в исходниках. Это не означает завершение финальной поставки: проверка на чистой Windows и финальная приёмка ещё впереди. Старые exe автоматически не обновляются.

- Расширенные фильтры, сохранение и повторный запуск подборок — [FR-P2](repetition.md#23-конструктор-свободной-сессии).
- Перемещение карточки между колодами отложено — [FR-C7](cards.md#4-управление-карточками).
- Эталон учебного набора и два отдельных модельных этапа не реализованы — [подготовка ИИ](ai-preparation.md#3-дальнейшая-работа).
- Изменения алгоритма, затухание забываний и новый порог «выучена» не согласованы — [границы повторения](repetition.md#82-границы-изменений-и-открытые-вопросы).

Один локальный профиль, одна колода на карточку; облака и аккаунтов нет. Ввод ответа и самопроверка работают на одном экране. Редактор уже выбран отдельным экраном, порог «выучена» — 21 день, импорт доступен с главной и из колоды, переименование — через меню; эти решения не являются открытыми вопросами.
