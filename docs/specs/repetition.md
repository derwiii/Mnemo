## 1. Назначение и граница режимов

Основное повторение проверяет знания по расписанию алгоритма и формирует долгосрочный прогресс. Свободная тренировка позволяет повторять материал для себя в любой момент. Она не является событием основного обучения, даже если выбранная карточка уже доступна по расписанию.

| Свойство | Основное повторение | Свободная тренировка |
|---|---|---|
| Вход | «Учить», «Учить всё», «Начать повторение» по расписанию | «Повторить», «Повторить всю колоду», конструктор свободной сессии |
| Начальный набор | Новые и изученные с наступившим сроком | Вся выбранная колода, вся библиотека или N случайных уникальных карточек |
| Порядок | Приоритет трудности/просрочки, новые вперемешку | Случайный |
| Проверка ввода и самопроверка | Раздел 2.1 | Те же правила |
| Подсказки | Доступны, снижают эффективную оценку | Доступны, основной прогресс не затрагивают |
| Возврат ошибки | После нескольких карточек | Так же внутри тренировки |
| CardState и расписание | Обновляются при подтверждении | Не меняются |
| ReviewLog и общая статистика | Попытки записываются и учитываются | Не записываются и не учитываются |
| Итоги прохода | Есть | Есть, только в памяти |
| Повтор только ошибок | Отдельное действие не добавляется | Доступен на итогах при наличии провалов |
| Новый запуск до срока | Успешные карточки с будущим сроком не выбираются | Разрешён сколько угодно раз |

- FR-S18. Свободный ответ не меняет ни одного поля CardState: status, due_at, interval_days, ease, lapses, reps. Новая карточка остаётся новой, изученная не меняет статус, провал не повышает трудность. Это относится ко всем свободным точкам входа и каждому проходу ошибок.
- FR-S19. Свободные ответы не создают постоянных записей ни в ReviewLog, ни в отдельной таблице, файле или кэше истории. Не нужны история тренировок, отдельная долговременная статистика, её фильтр в общем экране, восстановление после перезапуска и отложенное применение результатов к расписанию. Чтение карточек из БД допустимо. Явное изменение содержания карточки — отдельное действие, см. раздел 6.3.
- FR-S20. Итоги каждого свободного прохода показывают число подтверждённых попыток, успешных попыток, провалов и процент успеха. Имеющаяся разбивка по исходным оценкам может сохраняться. Факт и количество подсказок не создают отдельных категорий успешности. Срок жизни итогов и примеры — раздел 5.6.

Термины:

- Показ карточки сам по себе ещё не подтверждённая попытка.
- Подтверждённая попытка — успешная оценка либо «Далее» после ошибки/«Не помню».
- Исходная оценка — выбор пользователя; подтверждённый неверный ввод даёт again.
- Эффективная оценка — исходная после учёта подсказок, только для основного планировщика.
- Проход — исходный набор с возвратами ошибок. Повтор только ошибок начинает новый проход с собственными итогами.
- Успех — hard, good, easy, в том числе с подсказкой.
- Провал попытки — again; это не то же самое, что накопленный lapses.

## 2. Общий поток сессии

- FR-S1. Пользователь выбирает колоду (или «все колоды») и запускает сессию.
- FR-S2. Кнопки «Учить» и «Учить всё» сохраняют текущую логику занятий по расписанию: в очередь попадают все карточки с `due_at <= now` и все новые карточки. Дневных лимитов нет (решение пользователя); механизм лимитов сохранён в `settings.py` (`DAILY_NEW_LIMIT`, `DAILY_REVIEW_LIMIT`, по умолчанию `None`). Свободное повторение описано в разделах 2.2–2.3 этого документа.
- FR-S3. Показ карточки: сначала `front` (направление только «слово → перевод»). Кнопка «Подсказка» находится справа от слова и раскрывает ровно одну следующую подсказку по порядку (если есть); открытые подсказки показываются в правой колонке, которая появляется при первой подсказке и сдвигает основной блок влево ([дизайн сессии](design.md#7-экран-сессии)); повторное нажатие раскрывает следующую. После показа ответа подсказки скрываются. Поле ввода ответа видно сразу (см. раздел 2.1). Главная кнопка называется «Показать ответ», пока поле пусто, и «Проверить», когда в нём есть текст; она делает то же, что Enter (FR-S8).
- FR-S4. На вопросе «Не помню» (1) раскрывает ответ; «Далее» подтверждает again с учётом режима по FR-S5. После обычного раскрытия пользователь выбирает «Трудно» (2), «Хорошо» (3 / Enter), «Легко» (4). Tab открывает подсказку на вопросе, Esc завершает сессию; показ ответа и проверка описаны в FR-S8.
- FR-S5. Только подтверждённая попытка основного повторения записывается в ReviewLog и обновляет CardState через планировщик. Свободная попытка учитывается только в памяти текущего прохода: без постоянной истории, вызова планировщика и изменения основного прогресса. Это относится к успехам, провалам и повторам ошибок. Полная граница режимов — раздел 1.
- FR-S6. «Не помню» возвращает карточку в текущую сессию через короткий интервал (несколько карточек спустя), пока она не получит оценку выше «again».
- FR-S7. Сессию можно прервать в любой момент. В основном повторении уже подтверждённые ответы сохраняются. В свободной тренировке они доступны только для итогов текущего прохода; после выхода из него и закрытия приложения результаты не сохраняются.
- FR-S7a. В основном повторении, если подтверждённую оценку не удалось сохранить, показывается ошибка, карточка остаётся на экране ответа. Очередь, результаты и прогресс сессии меняются только после успешной записи; пользователь может повторить сохранение. Уже открытый ответ без подтверждённой оценки не записывается как попытка.

### 2.1 Проверка ответа: ввод и самопроверка на одном экране

- FR-S8. Переключателя между вводом и самопроверкой нет: на экране вопроса поле ввода ответа доступно и сразу сфокусировано, пользователь сам выбирает, как отвечать.
  - Enter, когда в поле есть текст (после обрезки пробелов): ответ проверяется (`answer_mode = typed`).
  - Enter или пробел, когда поле пусто (или состоит из одних пробелов), либо нажатие кнопки «Показать ответ»: ответ показывается без проверки, и пользователь сам ставит оценку (`answer_mode = self`).
  - Пробел при непустом поле печатается как обычный символ.
- FR-S9. На экране вопроса показываются: `front`, поле ввода, кнопка «Подсказка (n/m)» справа от слова и главная кнопка («Показать ответ» при пустом поле, «Проверить» при введённом тексте); рядом отдельное действие «Не помню» (FR-S4). Подробности внешнего вида: [дизайн сессии](design.md#7-экран-сессии).
- FR-S10. Нормализация перед сравнением (применяется и к вводу, и к каждому варианту перевода): приведение к нижнему регистру (`casefold`), обрезка пробелов по краям, схлопывание повторных пробелов, замена «ё» на «е», отбрасывание знаков препинания по краям (. , ! ? ; :).
- FR-S11. Проверка выполняется локально по всем строкам `translations` (1–10), раскрывая группы `{…|…}` по правилам разметки в [спецификации карточек](cards.md#5-разметка). Для каждого раскрытого варианта принимаются полная форма и форма без скобочных пояснений, например «бросать (привычку)» и «бросать». Пустые формы и пустой нормализованный ответ не принимаются. Сначала проверяется точное совпадение после нормализации, затем правила FR-S14. Семантическое сходство не вычисляется; неизвестный синоним сам по себе не является основанием принять ответ.
- FR-S12. После проверки показываются обычный результат (верно/неверно), все переводы и примеры. Введённый текст остаётся в поле без автоматической замены. Принятая опечатка или разрешённая перестановка отображается как обычный верный ответ, без отдельного сообщения «есть опечатка».
  - При неверном ответе действие «Добавить мой вариант» заменяет прежнюю кнопку «Я был прав» и открывает форму добавления перевода, предварительно заполненную введённым текстом. Пользователь может отредактировать его. Само открытие формы не меняет ни карточку, ни результат ответа и не записывает попытку.
  - Новый вариант должен быть непустым, проходить действующую валидацию переводов и не дублировать существующий вариант после нормализации. Добавление выполняется только явным сохранением; никакой ответ, включая принятый нечётким сравнением, автоматически не добавляется.
  - После успешного сохранения вариант добавляется в `translations` текущей карточки, ответ переводится в состояние верного; доступны три успешные оценки. При подтверждении оценки в основном повторении в ReviewLog сохраняются исходный введённый текст и `overridden = true`; в свободной тренировке это только результат в памяти. Сохранение перевода само по себе не записывает попытку и не выставляет оценку.
  - «Назад» / отмена возвращает к неверному ответу с исходным вводом; перевод не добавляется, оценка и журнал не меняются. При ошибке сохранения форма остаётся открытой, успех не засчитывается.
  - Лимит — 10 вариантов перевода на карточку. При достижении лимита форма сообщает об ограничении и не позволяет добавить одиннадцатый вариант. Автоматического удаления или замены существующих переводов нет; отмена остаётся доступной.
- FR-S13. Оценка после проверки введённого ответа: неверный ответ предлагает «Далее», которое подтверждает `again`, если пользователь не сохранил свой вариант по FR-S12; при верном ответе пользователь выбирает «Трудно» / «Хорошо» / «Легко», по умолчанию «Хорошо» (Enter). Правило подсказок FR-A2 действует так же.
- FR-S14. Если точного совпадения нет, применяются два независимых правила:
  - Допуск опечаток по расстоянию Дамерау — Левенштейна: вставка, удаление, замена символа и перестановка соседних символов. Допустимое расстояние зависит от длины строки; короткие ответы проверяются строже длинных. Длина — минимум длин нормализованного ответа и принимаемой формы без пробелов. До 4 символов включительно допуска нет; 5–9 символов — не более одной правки; от 10 символов — не более двух. Расстояние считается по полным нормализованным строкам, включая внутренние пробелы и пунктуацию.
  - Перестановка двух слов: если нормализованный ответ и принимаемая форма перевода состоят ровно из двух разделённых пробелом слов, принимается обратный порядок при точном совпадении самих слов. Например, «выглядеть хорошо» = «хорошо выглядеть». Это осознанное послабление с возможными ложными совпадениями, а не доказательство равнозначности. Для трёх и более слов перестановки автоматически не разрешаются; нужный порядок можно сохранить отдельным вариантом.
  - Правило перестановки слов не совмещается с допуском опечаток: после перестановки нечёткое сравнение не выполняется. Посимвольное расстояние считается только для исходного порядка строк.
  - Модели, эмбеддинги, косинусная близость и сетевые запросы в проверке не используются. Автоматическое распознавание новых синонимов и подготовка вариантов моделью, включая системный промпт для неё, в текущий объём не входят.

Критерии приёмки проверки ответа:
- Ввод «  ЁЖИК  » засчитывается для перевода «ежик».
- Для перевода «бросать (привычку)» ответ «бросать» засчитывается.
- «Выглядеть хорошо» принимается для «хорошо выглядеть»; «я хорошо выгляжу» не принимается для «хорошо я выгляжу» только на основании совпадения набора слов.
- Перестановка двух слов с дополнительной опечаткой не принимается правилом перестановки; нечёткое сравнение выполняется только с исходной формой перевода.
- Принятый по расстоянию ответ отображается как обычный верный; поле и `typed_answer` сохраняют исходный ввод, `translations` не меняется, `overridden = false`.
- «кит» не принимается для «кот», «ежки» — для «ежик»; «кокши» принимается для «кошки», «кошечк» — для «кошечка». Удаление буквы из пятисимвольного слова даёт более короткую строку из четырёх символов и не допускается. При длине от 10 символов допускаются две правки, но не три.
- Открытие и отмена формы «Добавить мой вариант» не меняют карточку, результат и ReviewLog.
- Сохранение нового варианта переводит ответ в состояние верного, но не записывает попытку до выбора оценки; затем в основном повторении в ReviewLog сохраняется `overridden = true`, планировщик обрабатывает успешную оценку с учётом подсказок. В свободном проходе планировщик и ReviewLog не используются.
- Пустой или дублирующий вариант не сохраняется; при 10 переводах одиннадцатый не добавляется; ошибка записи не приводит к принятию ответа.
- Enter на пустом поле (или на поле из одних пробелов) показывает ответ и даёт выбрать одну из трёх успешных оценок; в основном повторении в ReviewLog пишется `answer_mode = self`; в свободном режиме запись в БД не создаётся.
- Enter на поле с текстом проверяет ответ; в основном повторении в ReviewLog пишется `answer_mode = typed` и введённый текст; в свободном режиме они остаются только в памяти.
- Пробел на непустом поле ничего не показывает, а добавляется в текст.

### 2.2 Свободное повторение всей колоды

- FR-S15. На экране колоды доступно отдельное действие «Повторить всю колоду». Оно запускает повторение всех карточек выбранной колоды независимо от `due_at` и статуса, даже если сегодня по расписанию повторять нечего. Действие доступно для любой непустой колоды и может запускаться сколько угодно раз. «Учить» продолжает работать по FR-S2.
- FR-S16. Исходный набор включает каждую карточку колоды ровно один раз; порядок случайный при каждом новом проходе. Повторы после провала добавляются в очередь по FR-S6, поэтому общее число попыток может превышать размер исходного набора. Сессия заканчивается, когда у каждой карточки есть успешный ответ и очередь повторных попыток пуста; успешны `hard`, `good`, `easy`. Провалы не отбрасываются из результатов текущего прохода после последующего успеха; постоянной истории свободных ответов нет. Прерывание работает по FR-S7.
- FR-S17. На экране завершения свободного повторения доступно действие «Повторить только ошибки»: новый проход по уникальным карточкам, у которых был хотя бы один провал в завершённой сессии, даже если позднее в ней ответили успешно. Порядок заново перемешивается; провалы возвращаются по FR-S6, результаты существуют только в памяти нового прохода и не влияют на расписание или общую статистику. При отсутствии провалов действие недоступно. Полную колоду всегда можно снова запустить через FR-S15.

Уточнения границ сессии: при нехватке других карточек провал возвращается после оставшихся карточек, а для единственной карточки — сразу; ожидания по таймеру внутри сессии нет. Повтор ошибок доступен и в итогах досрочно завершённого прохода: учитываются только подтверждённые попытки этого прохода. Новый проход ошибок имеет собственные результаты и счётчик размера своей подборки.

Критерии приёмки свободного повторения:
- Для непустой колоды с будущими сроками всех карточек «Повторить всю колоду» запускает сессию; после её окончания можно сразу запустить ещё один полный проход.
- Карточки без провалов встречаются один раз за проход. Неверный ввод или «Не помню» возвращают карточку до успешного ответа, в том числе с оценкой «Трудно».
- Провал и последующий успех дают две попытки в итогах свободного прохода; обе оставляют CardState и ReviewLog без изменений.
- «Повторить только ошибки» включает каждую ошибочную карточку один раз в исходном наборе нового прохода; исправленные в предыдущем проходе ошибки также включаются.

### 2.3 Конструктор свободной сессии

- FR-P1. Нужен конструктор пула карточек для свободного повторения. Согласованный базовый сценарий: взять все карточки из всех колод либо выбрать N случайных уникальных карточек из всех колод независимо от расписания. Одна карточка не выбирается дважды в исходный набор; повторные попытки после провала работают по FR-S6. Постоянной истории и влияния на расписание нет по FR-S5; успех и провал определяются по FR-T4 и учитываются только в итогах прохода.
- FR-P2. Расширенные настройки конструктора требуют отдельного согласования. Не определены: выбор отдельных колод и фильтры (теги, статусы, сроки, трудность, история ошибок, ручной выбор), сохранение наборов или условий и отдельное действие повторного запуска прежнего набора. Эти решения не принимаются автоматически.
- FR-P3. N означает положительное целое число уникальных карточек исходного набора; возвраты после провала могут увеличить число попыток сверх N. Каждая карточка из всей библиотеки имеет равную вероятность попасть в выборку, доли колод не выравниваются. Если N больше доступного количества, экран показывает доступное число, предлагает уменьшить N и не запускает сессию; размер не уменьшается молча. Пустая библиотека не запускает сессию.
- FR-P4. Вход «Свободное повторение» расположен на главном экране «Колоды». На отдельном экране доступны «Все карточки из всех колод» и «N случайных карточек», доступное число карточек и запуск. Каждый запуск с этого экрана создаёт новую случайную выборку (либо перемешивает все карточки). «Повторить только ошибки» работает и для этих сессий по FR-S17; возврат ведёт на экран настройки. Сохранение и перезапуск прежнего полного набора в эту версию не входят.

## 3. Алгоритм планирования и подсказки

Алгоритм должен быть изолирован за интерфейсом `Scheduler`, чтобы его можно было заменить без переписывания остального приложения.

- FR-A1. В основном повторении используется упрощённый SM-2: интервалы растут с учётом ease; again уменьшает ease, а lapses увеличивает только при забывании из состояния review. Easy увеличивает ease. Диапазон ease — 1,3–3,0. Точные переходы и параметры — раздел 5. Свободная тренировка не вызывает планировщик.
- FR-A2. В основном повторении любая открытая подсказка снижает эффективную оценку на одну ступень среди успешных: easy → good, good → hard, hard → hard; again → again. Без подсказки оценка не меняется. Число открытых подсказок и их общее количество не имеют значения. Понижение выполняется один раз и остаётся под капотом: кнопки и исходный выбор не подменяются, стрелки и пояснения при ответе не показываются. В свободном режиме оценка для расписания не рассчитывается. Примеры — раздел 5.2.
- FR-A3. Карточки с большим lapses или низким ease получают повышенный приоритет среди доступных карточек основной очереди. Низкий ease также замедляет рост интервалов; lapses не является дополнительным множителем интервала. Будущий due_at не обходится ради трудности. Формулы — раздел 5.5.
- FR-A4. Порядок внутри сессии: просроченные и «трудные» впереди, новые вперемешку с повторениями, а не блоком.
- FR-A5. Планировщик детерминирован при одинаковых входных данных (кроме явной случайности в порядке; для тестов задаётся seed).

Идея на будущее (не v1): заменить SM-2 на более современный алгоритм (например, семейство FSRS), используя накопленный ReviewLog.

## 4. Общая статистика

- FR-T1. Экран общей статистики учитывает только основное повторение: всего карточек, по статусам (new/learning/review), число попыток за сегодня и за последние 30 дней. За последние 30 дней показываются процент успешных ответов, число провалов и число уникальных повторённых карточек. Процент успешных = 100 × число успешных попыток / число всех подтверждённых попыток; при отсутствии попыток показывается «—». Правила успеха и провала — FR-T4.
- FR-T2. Список «самых трудных карточек»: топ-N по `lapses` и низкому `ease`, с переходом к редактированию.
- FR-T3. Попытки и успешность рассчитываются по ReviewLog только основного повторения, состояния и трудность — по CardState. Свободные результаты не являются источником общей статистики.
- FR-T4. Провал — неверный введённый ответ, подтверждённый переходом «Далее» без успешного добавления своего варианта по FR-S12, либо оценка «Не помню» при самопроверке (`again`). Успех — `hard`, `good` или `easy`, в том числе с подсказкой и после добавления своего варианта по FR-S12. Подсказки продолжают снижать эффективную оценку планировщика по FR-A2, но сами по себе не превращают успех в провал. Статистический провал не равен `CardState.lapses`: последний считает забывания при переходе из review в learning, независимо от отображаемой метки «выучена».
- FR-T5. В общую статистику входят только основные попытки. Свободные проходы и повторы их ошибок исключены и не записываются в БД. Основной провал и последующий успех — две попытки, один провал и один успех; уникальная карточка считается один раз. Исправление не удаляет прошлую ошибку. База пользователя уже сброшена; восстанавливать или разделять накопленную смешанную историю не требуется. Автоматический сброс базы при реализации не нужен.

### 4.1 Сохранённые критерии приёмки

- Карточка, на которую три раза подряд ответили «не помню», имеет меньший интервал и ease, чем карточка, на которую три раза ответили «хорошо».
- При равной просрочке больший difficulty даёт более раннее место среди доступных изученных карточек. Сам lapses не увеличивает число показов; повторные ошибки возвращают карточку в текущую очередь, а низкий ease замедляет рост будущих интервалов (5.4–5.5).
- Ответ «easy» с одной из нескольких открытых подсказок обрабатывается как «good», но в ReviewLog хранится исходная «easy» и `hints_used`; число подсказок не меняет этого правила; `good` с любой подсказкой обрабатывается как `hard` (FR-A2).
- Закрытие приложения не теряет подтверждённые основные ответы; результаты свободной тренировки не сохраняются.

## 5. Подробные правила и примеры

### 5.1 Подтверждение ответа и управление

| Действие | Основное повторение | Свободная тренировка |
|---|---|---|
| Открыть подсказку | Запомнить использование до подтверждения | Открыть для себя |
| Показать ответ или проверить ввод | Показать результат, ещё не записывать попытку | Ещё не учитывать попытку |
| Нажать «Не помню» на вопросе | Раскрыть ответ, дождаться «Далее» | То же |
| Выбрать успешную оценку | Атомарно обновить CardState и ReviewLog, затем перейти дальше | Добавить результат в память прохода и перейти дальше |
| «Далее» после ошибки/«Не помню» | Записать again, изменить состояние и вернуть в очередь | Учесть один провал в памяти и вернуть в очередь |
| Выйти без подтверждения ответа | Не создавать попытку | Не учитывать попытку |

Открытие формы «Добавить мой вариант», отмена и само сохранение перевода не подтверждают попытку. Черновик поля при нажатии «Не помню» не является проверенным вводом: режим этой попытки — self. Оценка не выбирается автоматически по времени ответа. «Хорошо» по Enter — явное подтверждение пользователя.

На вопросе 1 вызывает «Не помню», Tab открывает одну следующую подсказку, не меняя введённый текст. После раскрытия/верного ввода 2/3/4 выбирают «Трудно»/«Хорошо»/«Легко», Enter — «Хорошо»; команда 1 уже отключена. При ошибке или «Не помню» Enter выполняет «Далее». Shift+Tab остаётся обратной навигацией. После раскрытия ответа Tab служит навигации.

Esc действует как завершение: без подтверждённых попыток — назад, с попытками — итоги. На итогах команда завершения отключена. Автоповтор 1, Tab и Esc отключён. Длинное содержимое прокручивается без перекрытия действий; при смене карточки/состояния прокрутка возвращается к началу. Визуальные размеры определены в [дизайне](design.md).

### 5.2 Подсказки: бинарное правило

| Исходная оценка | Подсказок не открывали | Открыли хотя бы одну |
|---|---|---|
| Не помню (again) | again | again |
| Трудно (hard) | hard | hard |
| Хорошо (good) | good | hard |
| Легко (easy) | easy | good |

Понижение применяется один раз. Easy с подсказкой превращается в good, а не последовательно в hard. Одна подсказка из одной, одна из пяти и все пять дают одинаковый результат. Число подсказок в карточке не создаёт разных правил оценки.

Если подсказок нет или все открыты, следующая не открывается. После раскрытия ответа подсказки скрыты, но факт их использования сохраняется до подтверждения. При каждом новом показе, в том числе после провала той же карточки, использование начинается с нуля. Подсказка прошлой попытки не понижает новый ответ без подсказки.

Кнопки и итоги показывают исходный выбор. В основном журнале сохраняются исходная оценка и hints_used. Эффективная оценка нужна для расчёта; отдельно хранить или показывать её не требуется. Число hints_used может оставаться технической подробностью журнала и счётчика «n/m», но планировщик использует только признак hints_used > 0. Удалять поле или менять схему ради этого правила не требуется.

Пример: у карточки review интервал 10 дней, ease = 2,5. Пользователь открыл подсказку и нажал «Хорошо». В истории и итогах остаётся «Хорошо», расписание использует «Трудно»: интервал 12 дней, ease = 2,35. В общей статистике это один успех. Стрелок «Хорошо → Трудно», предупреждений и отдельной статистики подсказок нет.

В свободной тренировке расчёт эффективной оценки для расписания вообще не производится. Любая из трёх успешных оценок — один успех; подсказка не превращает его в провал.

### 5.3 Параметры и переходы основного планировщика

Сохраняются существующий упрощённый SM-2 и числовые параметры из src/mnemo/settings.py. Смена алгоритма в это согласование не входит.

| Параметр | Значение |
|---|---|
| Начальный ease | 2,5 |
| Границы ease | 1,3–3,0 |
| Изменение ease при again | −0,20 |
| Изменение ease при hard из review | −0,15 |
| Изменение ease при easy | +0,15 |
| Множитель интервала hard из review | 1,2 |
| Дополнительный множитель easy из review | 1,3 |
| Сокращение интервала после забывания из review | ×0,5 |
| Минимальный интервал расчёта review | 1 день |
| Максимальный интервал | 365 дней |
| Ближайший срок после again | 10 минут |
| Начальный срок hard | 0,5 дня, то есть 12 часов |
| Базовый интервал good при обучении | 1 день |
| Базовый интервал easy при обучении | 3 дня |
| Возврат ошибки в текущей сессии | После 3 других карточек, если они есть |
| Порог отображения «выучена» | 21 день при состоянии review |

Даты считаются от момента подтверждения текущего ответа. Интервалы могут быть дробными; принудительного округления до целых суток нет. Каждая основная подтверждённая попытка увеличивает reps на 1. После изменения ease ограничивается своим диапазоном, интервал — максимумом 365 дней. В таблицах ниже используется эффективная оценка после подсказок.

**Новая карточка или обучение: состояния new и learning.**

| Оценка | Новый статус | Интервал и следующий срок | Коэффициент и забывания |
|---|---|---|---|
| again | learning | Прежний interval_days сохраняется; срок через 10 минут | ease − 0,20; lapses без изменений |
| hard | learning | interval_days = max(прежний; 0,5); срок через 12 часов | ease и lapses без изменений |
| good | review | interval_days = max(прежний; 1); срок через этот интервал | ease и lapses без изменений |
| easy | review | interval_days = max(прежний; 3); срок через этот интервал | ease + 0,15; lapses без изменений |

У новой карточки interval_days равен 0. При доучивании забывавшейся карточки может сохраняться больший интервал. Существующая особенность learning + hard: срок всегда 12 часов, хотя сохранённый interval_days может быть больше 0,5. Здесь фиксируется текущее поведение; выравнивать эти значения или менять алгоритм этим этапом не требуется.

**Регулярное повторение: состояние review.** Пусть I = max(прежний interval_days; 1), E — прежний ease, Enew — коэффициент после изменения и ограничения диапазоном.

| Оценка | Новый статус | Новый интервал | Следующий срок | Коэффициент и забывания |
|---|---|---|---|---|
| again | learning | max(1; I × 0,5) | Через 10 минут | Enew = E − 0,20; lapses + 1 |
| hard | review | max(1; I × 1,2) | Через новый интервал | Enew = E − 0,15; lapses без изменений |
| good | review | max(I + 1; I × E) | Через новый интервал | ease и lapses без изменений |
| easy | review | max(I + 1; I × Enew × 1,3) | Через новый интервал | Enew = E + 0,15; lapses без изменений |

Во всех строках новый интервал ограничен 365 днями. Срок успешного ответа использует ограниченный интервал. У again сохранённый интервал и время до ближайшего показа — разные величины.

Пример без подсказок: review, интервал 10 дней, ease = 2,5. «Трудно» даёт 12 дней и 2,35; «Хорошо» — 25 дней и 2,5; «Легко» — 34,45 дня и 2,65; «Не помню» — срок через 10 минут, сохранённый интервал 5 дней и коэффициент 2,3. Если затем в обучении ответить «Хорошо», срок назначается через сохранённые 5 дней от этого ответа.

### 5.4 Ранний показ и возврат после ошибки

Основная начальная очередь не выбирает изученную карточку до due_at. Свободный показ до срока не является событием планировщика: интервал не увеличивается ни полностью, ни частично, не переносится и не пересчитывается.

Пример: карточка назначена на завтра с интервалом 10 дней. Пять свободных успехов, затем свободный провал оставляют тот же срок на завтра, интервал 10 дней, коэффициент, статус, счётчики и число карточек «к повторению». Новая карточка после любого числа свободных успехов остаётся новой для основного алгоритма.

Возврат ошибки в основной сессии — часть доучивания. После удаления текущей карточки из головы очереди её вставляют после первых трёх оставшихся. Если других карточек две, она появится после двух, если нет ни одной — сразу. Таймер сессии не ждёт 10 минут. Следующий основной ответ обрабатывается по правилам learning, а не как новый полный рост review.

Несколько again в обучении дают несколько провалов статистики и снижений ease, но не несколько увеличений lapses: он увеличился только при переходе из review в learning. Успех не удаляет провалы и не уменьшает lapses.

После hard, good или easy карточка выбывает из текущей очереди. Даже если сессия длится до нового срока, автоматического повторного добавления по таймеру нет: доступная очередь строится при следующем основном запуске. Отдельный суточный предел роста или новый механизм досрочного основного повторения не вводятся.

### 5.5 Трудность, порядок и статусы

Отдельного общего рейтинга в баллах и отдельной «пузырной системы» нет. «Всплывание» трудных карточек — приоритет в основной очереди.

`difficulty = lapses + 2 × max(0; 2,5 − ease)`

`priority = 2 × difficulty + min(30; max(0; дней просрочки))`

Просрочка рассчитывается по фактическому времени и бывает дробной. Из изученных карточек выбираются только due_at <= now. Они сортируются по убыванию приоритета, при равенстве — по более раннему due_at, затем ID. Новые сначала упорядочиваются по времени создания и ID, затем вставляются в случайные позиции. Поэтому перед трудной карточкой может оказаться новая. Дневные лимиты отключены; сохранённый механизм лимитов этим изменением не включается.

Свободная выборка не использует этот приоритет и не меняет его. Она не убирает доступную основную карточку из задолженности и не создаёт новую задолженность.

«Самые трудные» — до 10 карточек с reps > 0 и difficulty > 0. Сортировка: убывание difficulty, затем убывание lapses, затем ID. Это не процент ошибок. Накопленные lapses после успехов не обнуляются; ease восстанавливается только по правилам планировщика. Затухание старых забываний не согласовано.

В списке карточек: «новая» при new; «выучена» при review и интервале от 21 дня; «учится» в остальных случаях. Разбивка общей статистики использует внутренние new/learning/review, поэтому число review не равно числу меток «выучена». Объединение или переименование категорий в этот этап не входят.

### 5.6 Итоги прохода и общая статистика

Процент успеха — round(100 × успешные попытки / все подтверждённые попытки). Для общей статистики источник — только основные попытки, для свободных итогов — результаты текущего прохода. Без попыток процент — «—», а не 0%/100%.

Пример свободного прохода: одну карточку дважды не вспомнили, затем нажали «Трудно». Итог: 3 попытки, 1 успех, 2 провала, 33% успеха. Карточка пройдена; прошлые ошибки остаются в итогах и включают её в «Повторить только ошибки». Подсказки не меняют подсчёт. Три успешные оценки не имеют разного веса в проценте.

«Повторить только ошибки» собирает уникальные карточки с хотя бы одним again, включая позже исправленные, и перемешивает их. Новый проход имеет свои итоги. Если после 33% в новом проходе все попытки успешны, новые итоги показывают 100%, а не суммарный процент двух проходов. Постоянной истории свободных проходов нет.

Досрочное завершение показывает только подтверждённые попытки, без провалов за непройденные карточки. При непустой очереди нельзя объявлять весь набор повторённым. Повтор ошибок доступен и после досрочного завершения с провалами; без провалов недоступен. Без попыток завершение возвращает назад. Результаты доступны в текущем проходе и на его итогах; выход или новый проход прекращают хранение прежних результатов. Итоги и очередь не восстанавливаются после закрытия приложения.

«Сегодня» в общей статистике — с начала местных календарных суток; последние 30 дней — скользящий период now − 30 дней. Процент округляется до целого действующим round. Каждая попытка считается отдельно; уникальные карточки — один раз по ID за период. Нет отдельных процентов с подсказками/без, взвешенных баллов или общего рейтинга пользователя.

## 6. Хранение и границы данных

### 6.1 Основной прогресс и журнал

Типы данных сохраняются: идентификаторы — UUID; даты — datetime; status/grade/answer_mode — перечисления; interval_days/ease и интервалы журнала — float; lapses/reps/hints_used/response_time_ms — int; overridden — bool; typed_answer — необязательная строка.

CardState существует у учебной карточки независимо от запуска повторения. Свободная тренировка читает содержимое, но учебное состояние не изменяет.

| Поле CardState | Значение |
|---|---|
| card_id | Связь 1:1 с Card |
| status | new, learning, review |
| due_at | Следующий срок основного повторения |
| interval_days | Сохранённый интервал основного планировщика |
| ease | Коэффициент роста, начальное значение 2,5 |
| lapses | Число забываний при переходе из review в learning |
| reps | Все подтверждённые основные попытки |

ReviewLog содержит только основные попытки. Записи добавляются, не переписываются при последующих успехах. Удаление карточки или колоды, как и прежде, может каскадно удалить её историю.

| Поле ReviewLog | Значение |
|---|---|
| id, card_id, reviewed_at | Идентификаторы и момент подтверждения |
| grade | Исходная again/hard/good/easy, до подсказок |
| hints_used | Количество открытых подсказок; для оценки важно только больше ли нуля |
| response_time_ms | Время от показа вопроса до раскрытия/проверки/«Не помню», без времени выбора оценки |
| answer_mode | typed — проверен ввод; self — самопроверка или «Не помню» |
| typed_answer | Исходный проверенный ввод, только для typed |
| overridden | Неверный ввод принят после явного сохранения своего перевода; только для typed |
| interval_before / interval_after | Сохранённые интервалы; не обязательно время до ближайшего показа |

Самопроверка не сохраняет черновик ввода как typed_answer; overridden у неё false. Старые записи overridden от прежней команды «Я был прав» не требуют переинтерпретации, если такая база встретится при разработке. Скорость, способ ответа и overridden не являются дополнительными множителями расписания. После принятия своего варианта действует выбранная успешная оценка с общим учётом подсказки.

### 6.2 Атомарность и отсутствие скрытых записей

В основном режиме CardState и ReviewLog изменяются одной транзакцией. Ошибка оставляет экран ответа, очередь, прогресс и итоги неизменными; повторное подтверждение должно записать одну попытку. До успешной записи переходить дальше нельзя.

В свободном режиме запись учебного результата не производится вообще. Недостаточно записать свободный ответ и затем отфильтровать его из статистики либо восстановить прежний CardState: планировщик не вызывается. Результаты и очередь живут в памяти прохода и его итогов, без постоянных таблиц, файлов настроек или кэша истории.

Постоянная история содержит только основной режим. Добавлять тип сессии ради хранения свободных ответов не требуется. Организация методов и объектов выбирается при реализации; граница режимов должна быть явной и проверяемой во всех точках входа.

### 6.3 Явные изменения содержания карточки

«Не сохранять свободную тренировку» относится к ответам, результатам, расписанию и статистике. «Добавить мой вариант» остаётся явным редактированием Card.translations: новый перевод должен пережить выход из тренировки. Это действие само по себе не меняет CardState и не создаёт ReviewLog; следующая свободная оценка также ничего не записывает в прогресс.

Запретить редактирование перевода в свободном режиме пользователь не просил; ограничение не вводится. Случайные ответы автоматически не добавляются. Сохраняются явное подтверждение, валидация, лимит 10 переводов, обработка ошибки и отмена по FR-S12.

### 6.4 Накопленный прогресс

По сообщению пользователя, база уже сброшена, приложение используется одним человеком. Восстанавливать состояние до прежних свободных ответов и классифицировать старую смешанную историю не требуется. Это не разрешение удалять базу при реализации или запуске: автоматического сброса данных быть не должно. Формат карточек, JSON-экспорт и промпт подготовки карточек не меняются.

## 7. Критерии приёмки новых правил

Эти проверки дополняют критерии FR-S/FR-P/FR-A/FR-T и служат требованиями к дальнейшему сохранению поведения. Основные автоматические проверки находятся в tests/domain/test_scheduler.py, tests/test_review_flow.py и tests/ui/test_free_review_ui.py.

1. Основной ответ меняет CardState, добавляет ровно одну ReviewLog и отражается в общей статистике.
2. Свободные успех и провал на new, learning и review оставляют полностью неизменными CardState и число ReviewLog.
3. То же проверяется при запуске с главной, из колоды, конструкторов «все» и «N случайных», при повторении ошибок.
4. Свободный проход не меняет число «к повторению», статусы, список трудных, число основных попыток и общую успешность. Для сравнения фиксируется одинаковый момент времени, чтобы естественное наступление срока не выглядело эффектом тренировки.
5. Новая карточка после свободных успехов остаётся новой; review с будущим сроком после свободного провала остаётся с тем же сроком.
6. Для всех четырёх оценок проверяется FR-A2 без подсказок, с одной из нескольких, с единственной и со всеми. Good с любой даёт hard, easy с любой даёт good. Понижение происходит один раз.
7. Новый показ сбрасывает подсказку, в том числе после провала. Скрытие подсказки после раскрытия ответа до подтверждения не сбрасывает её использование.
8. Исходные оценки сохраняются в основном журнале и итогах, а состояние соответствует эффективной. Стрелок, подмены нажатого выбора и отдельных категорий подсказок нет.
9. Два свободных провала и успех дают 3 попытки, 2 провала, 1 успех, 33% в итогах и нулевое изменение общей статистики. Hard с подсказкой тоже успех.
10. После перезапуска свободных ответов, очереди и итогов нет в постоянном хранилище, основной прогресс сохранился.
11. Повтор ошибок включает уникальные карточки с любым провалом, даже исправленным; новый проход имеет независимые итоги и также не меняет прогресс.
12. Досрочный выход учитывает только подтверждённые попытки, без штрафа за непройденные; неполный набор не объявляется пройденным. Без попыток выход идёт назад; отсутствие данных даёт «—» для процента.
13. Короткие очереди возвращают ошибку после доступных 0–3 карточек без таймера. Основной again отдельно назначает срок через 10 минут, следующий ответ использует learning.
14. Ошибка основной транзакции не сохраняет половину результата и не двигает очередь. Повтор сохранения не дублирует попытку. Свободный переход не зависит от записи учебного результата в БД.
15. Явно сохранённый свой перевод в свободном режиме остаётся в Card после перезапуска без изменения CardState/ReviewLog. Отмена или ошибка сохранения не принимают неверный ответ.
16. Многократные свободные проходы не увеличивают и не сокращают интервал; нет отложенного применения результатов при выходе или запуске основного повторения.

## 8. Состояние реализации и границы дальнейших изменений

### 8.1 Отличия от прежних требований

| Область | Прежняя реализация | Согласованное поведение |
|---|---|---|
| Свободный ответ | Общая запись с основным, изменение CardState/ReviewLog | Только память прохода |
| Общая статистика | Все сессии вместе | Только основное повторение |
| Подсказки | Частичные ограничивают easy до good, все ограничивают максимум до hard | Любое использование: easy → good, good → hard |
| Свободные итоги | Число попыток и разбивка оценок | Дополнительно явно успехи, провалы и процент; без истории |
| Отображение снижения | Эффективная оценка отдельно не показывается | Расчёт остаётся под капотом, без стрелок и пояснений |
| Накопленная история | Смешанные попытки без типа сессии | База уже сброшена, восстановление не требуется |

Новые правила реализованы в исходниках. Основные сессии подключены к записи ReviewLog и CardState, свободные используют только результаты SessionScreen. Итоги свободных проходов показывают успехи, провалы и процент; effective_grade использует бинарный признак подсказки. Проверки охватывают все пять входов в свободную тренировку и три статуса карточки, повтор ошибок, неизменность БД/статистики/очереди, повторное открытие базы, сохранение своего перевода, все комбинации оценок с подсказками и откат основной транзакции. Итоги визуально проверены при минимальном окне 760 × 600. Схема БД и формат данных не менялись; сборку dist нужно обновлять отдельно, если приложение запускается из старого exe.

Проверка 13 ноября 2026: общий прогон дал 278 успешных тестов и 1 пропуск; оставшаяся проверка второго экземпляра прошла отдельно вне песочницы, поскольку ей нужен системный локальный канал. Итого проверено 279 успешных тестов, 1 пропущен. Для UI-тестов используется тот же стиль Fusion, что и при штатном запуске приложения; это устраняет аварии нативного стиля Windows в offscreen-окружении. Дополнительно выполнены compileall, проверка ссылок документации и git diff --check.

### 8.2 Границы изменений и открытые вопросы

Сохраняются параметры SM-2, смысл lapses, формулы приоритета, возврат ошибок, порядок подсказок, проверка текста и добавление своего перевода. Затухание старых забываний, изменение порога «выучена», веса оценок, зависимость интервала от скорости не согласованы и не вводятся.

Расширенный конструктор открыт по FR-P2: несколько выбранных колод, теги, статусы, сроки, трудность, история ошибок, ручной отбор и сохранение наборов/условий не добавляются автоматически. Истории свободных ошибок больше нет; будущий фильтр по ней потребовал бы отдельного пересмотра правил хранения.

Отдельный перезапуск прежнего полного набора с итогов не согласован. Согласованы повтор ошибок и новый запуск колоды/конструктора. FSRS остаётся идеей на будущее. Интеграция модели остаётся за рамками повторения. Подготовка карточек и разметка определены в [ai-preparation.md](ai-preparation.md) и [cards.md](cards.md); их выделение 16 ноября не меняет правила обучения.
