# Mnemo: импорт и экспорт JSON

Обновлено 16 ноября 2026. Действующие требования; перенесены из основной спецификации без изменения согласованного поведения.

Этот документ определяет обмен учебным содержимым (FR-I, FR-E, FR-H); модель карточки и разметка — в [cards.md](cards.md). [Карта спецификаций](../../spec.md).

## 1. Импорт

- FR-I1. Импорт из `.json` файла (выбор файла) и из вставленного текста.
- FR-I2. Целевая колода: существующая (выбрать) или новая (создаётся по данным из файла или вводится вручную).
- FR-I3. Перед записью показывается предпросмотр: число валидных карточек, число ошибочных, число дубликатов, первые N карточек.
- FR-I4. Импорт атомарный на уровне подтверждения: пользователь подтверждает, после чего валидные записываются одной транзакцией.
- FR-I5. Невалидные записи не блокируют импорт валидных; все ошибки перечислены с указанием индекса записи и причины.
- FR-I6. Дубликаты (по правилу FR-C6) обрабатываются по выбору пользователя: пропустить (по умолчанию), добавить всё равно, обновить существующую.
- FR-I7. Импортированные карточки при создании получают `status = new`. Режим «обновить существующую» меняет содержимое карточки без сброса CardState и ReviewLog (FR-C3).
- FR-I8. Максимальный размер файла: 5 МБ; максимум 5000 карточек за импорт (константы конфигурируемы).

Дубликаты ищутся в целевой колоде и среди предыдущих записей файла по [FR-C6](cards.md#4-управление-карточками). При режиме «обновить» применяется первая запись для существующей карточки; последующие повторы пропускаются. Номера записей в ошибках начинаются с 1.

## 2. Формат JSON (schema_version = 1)

```json
{
  "schema_version": 1,
  "deck": {
    "name": "Phrasal verbs, unit 3",
    "description": "Из учебника, стр. 42",
    "source_language": "en",
    "target_language": "ru"
  },
  "cards": [
    {
      "front": "to give up",
      "translations": ["сдаваться"],
      "examples": [
        { "text": "I failed twice, but I won't give up.", "translation": "Я потерпел неудачу дважды, но не сдамся." }
      ],
      "hints": ["После нескольких неудач человек решает, стоит ли продолжать попытки."],
      "tags": ["phrasal-verb"]
    }
  ]
}
```

Правила:
- `schema_version` обязателен для объекта-обёртки. Упрощённый корневой массив не содержит версии и трактуется как формат v1. Неизвестная версия отклоняется с понятным сообщением.
- Блок `deck` опционален. Если он есть, а пользователь выбрал «новая колода», берутся его значения; если выбрана существующая, `deck` игнорируется.
- Допускается корневой массив карточек без обёртки (`[ {...}, {...} ]`) как поддерживаемый упрощённый формат.
- Неизвестные поля игнорируются с предупреждением, а не ошибкой.
- Кодировка UTF-8.

## 3. Экспорт

- FR-E1. Экспорт колоды в тот же JSON-формат (для переноса и резервной копии учебного содержимого). Прогресс, история повторений, входящие, настройки приложения и обложки в v1 не экспортируются. JSON колоды не является полной резервной копией базы.

## 4. Помощь с получением JSON

- FR-H1. В диалоге импорта есть кнопка «Скопировать промпт для ИИ». Промпт объясняет ИИ-ассистенту, как преобразовать документ/PDF/изображение со словами в JSON этой схемы, и содержит пример. Текст промпта хранится в проекте отдельным файлом.

Рабочий текст — [src/mnemo/resources/ai_prompt.txt](../../src/mnemo/resources/ai_prompt.txt); его требования — [подготовка карточек через ИИ](ai-preparation.md). Приложение копирует текст, но не вызывает модель.

## 5. Критерии приёмки

- Корректный файл на 200 карточек импортируется менее чем за 2 секунды.
- Файл, где 3 записи из 50 некорректны: импортируются 47, пользователь видит список из 3 ошибок с индексами.
- Повторный импорт того же файла при режиме «пропустить дубликаты» не добавляет ничего.
- Файл с неверным JSON-синтаксисом даёт читаемую ошибку без падения приложения.
- Обновление существующей карточки импортом сохраняет её прогресс и историю; добавленная карточка получает новое состояние.
- Объект без `schema_version` отклоняется; корректный корневой массив принимается как v1.
